# Бэктест спотовых стратегий на истории BTC H1 (2 года)

Каталог содержит код и результаты сравнения трёх стратегий:

| Стратегия | Источник описания | Реализация |
|---|---|---|
| Buy&Hold (эталон) | — | `engine.buy_and_hold` |
| GridRB 70/30 | `docs/GridRB_spec.md` | `strategies.GridRB` |
| Два режима 70/30 | `docs/spec.md`, раздел «Стратегия «Два режима 70/30»» | `strategies.TwoModes7030` |
| Trend-Adaptive Grid | `docs/spec.md`, раздел «Стратегия "Trend-Adaptive Grid"» | `strategies.TrendAdaptiveGrid` |

Текущий бот (`main.py`, `modules/`) не изменялся.

## Данные

- Источник: `data-api.binance.vision` (публичный дата-API Binance; `api.binance.com`
  из этого окружения гео-ограничен). Пара `BTCUSDT`, интервал `1h`.
- Окно: **2024-11-02 11:00 → 2026-11-02 11:00 UTC**, 17 521 бар — ровно окно
  из `docs/GridRB_spec.md` §9.
- Файл: `data/btc_h1_2y.csv` (скачивается `fetch_data.py`).
- Оговорка: это BTCUSDT на Binance, а не Hyperliquid spot (UBTC/USDC). Уровни и
  микроструктура немного другие; для сравнения стратегий между собой и с hold
  этого достаточно. Совпадение с таблицей §9 (см. ниже) подтверждает, что
  расхождение мало.

## Модель исполнения

Единая для всех стратегий, взята из `docs/GridRB_spec.md` §2:

- maker 0.040 %, taker 0.070 %, проскальзывание маркета 0.020 %;
- лимитный buy исполняется, если `l <= L`, по `min(o, L)`;
- лимитный sell — если `h >= S`, по `max(o, S)`;
- внутри бара сначала покупки, потом продажи;
- buy не исполняется при нехватке USDC, sell — на `min(q, B)`;
- минимальный нотионал $10;
- стресс-вариант: все издержки ×2.

## Результаты (2 года, старт $10 000, базовые издержки)

| Стратегия | Финал | Доход | Excess vs hold | maxDD | Сделок |
|---|---|---|---|---|---|
| Buy&Hold | $11 180 | +11.8 % | — | −53.7 % | 1 |
| GridRB 70/30 | $11 192 | +11.9 % | **+$11 (+0.11 п.п.)** | **−40.7 %** | **325** |
| Два режима 70/30 | $9 079 | −9.2 % | −$2 101 (−21.0 п.п.) | −40.6 % | 5 407 |
| Trend-Adaptive Grid | $11 559 | +15.6 % | **+$379 (+3.79 п.п.)** | −35.5 % | 3 366 |

Валидация: GridRB воспроизводит справку `docs/GridRB_spec.md` §9 почти точно —
финал $11 192 против $11 185, maxDD −40.7 % против −40.7 %, 325 сделок против 325.
Это подтверждает корректность движка и GridRB; расхождения по остальным
стратегиям объясняются неоднозначностью их описаний (см. ниже).

## Принятые допущения (спецификации неоднозначны)

**Два режима 70/30** (`docs/spec.md`):
- `H_L` — максимум high за `N=168` баров (в спеке `N` не задан);
- старт в режиме B, чтобы разрешить первый вход;
- ключевой выбор — что считать «ребалансировкой»:
  - `rebalance="none"` — только три типа входов из «Режим B — правила»;
  - `rebalance="gated"` — докупка до целевой доли, если нет висящего усреднения;
  - `rebalance="always"` — докупка до целевой доли на каждом шаге (основной
    вариант: именно он даёт ~70 % экспозиции и maxDD ≈ −40 %, как в справке §9).
- `sensitivity.csv` показывает, что итог меняется от −23 до +7 п.п. в зависимости
  от этой трактовки. Это свойство спецификации, а не ошибка прогона.

**Trend-Adaptive Grid** (`docs/spec.md`):
- старт: 50 % в Ядро, 50 % в USDC;
- докупка Ядра — один раз на каждое новое пересечение вниз уровня `0.9·ATH`
  (триггер взводится заново на новом ATH);
- защёлка на новом ATH переносит половину BTC Спутника в Ядро (тейки
  оставшейся половины сохраняются);
- размер вдогонку убывает линейно: `q·USDC·(1 − w/0.7)`.

**GridRB** реализован дословно по `docs/GridRB_spec.md` §5, §7.

## Ограничения

- Результаты — на одном историческом пути; это не гарантия будущей доходности.
- Комиссии и проскальзывание заданы как в спеке; реальные могут отличаться.
- Сценарии S1–S4 — синтетика: реальный H1-блок умножается на экспоненциальный
  дрейф, чтобы попасть в целевую доходность. Внутрибаровые пропорции и
  волатильность реальные, но это не точная историческая выборка.
