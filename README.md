# Hyperliquid Bot

Автоматизированный торговый бот для spot торговли на децентрализованной платформе Hyperliquid с поддержкой усреднения позиций, пирамидинга и автоматических TP ордеров.

## 🚀 Особенности

- **Spot торговля** с автоматическим усреднением позиций
- **Пирамидинг** при движении цены в прибыльном направлении
- **Автоматические TP ордера** для каждой позиции
- **Web3 интеграция** - работа с кошельками через приватные ключи
- **Telegram уведомления** о сделках, профитах и ошибках
- **Многокошельковая торговля** - поддержка нескольких аккаунтов одновременно
- **Статистика операций** - запись в Excel файлы
- **База данных PostgreSQL** (опционально) для отслеживания истории сделок
- **Ограничение частоты логов** для уменьшения спама

## 📋 Требования

- **Python 3.8+**
- **Web3 кошелек** с приватным ключом
- **Telegram Bot Token** для уведомлений
- **PostgreSQL** (опционально, для расширенной функциональности)
- **RPC провайдер** (Infura, Alchemy, QuickNode или публичный RPC)

## ⚙️ Настройка

### 1. Настройка кошельков (`input_data/wallets.txt`)

Формат файла: `label|wallet_address|private_key|proxy`

```
Acc1|0x1234567890123456789012345678901234567890|0xabcdef1234567890abcdef1234567890abcdef1234567890abcdef1234567890|http://proxy:port
Acc2|0x0987654321098765432109876543210987654321|0xfedcba0987654321fedcba0987654321fedcba0987654321fedcba0987654321|
```

- **label** - метка аккаунта (для удобства в логах)
- **wallet_address** - адрес кошелька (0x...)
- **private_key** - приватный ключ кошелька (0x...)
- **proxy** - прокси сервер (опционально, можно оставить пустым)

### 2. Настройка Telegram (`input_data/tg_bot_tokens.txt`)

```
TG_BOT_TOKEN        = '12345:ABCDE' # токен бота уведомлений
PROFIT_BOT_TOKEN    = '7848...GmU' # токен бота уведомлений (только о профитах)
TG_USER_ID          = [332...342] # тг айди куда должны приходить уведомления
```

- **TG_BOT_TOKEN** - основной токен бота для всех уведомлений
- **PROFIT_BOT_TOKEN** - токен бота для уведомлений о профитах (можно использовать тот же)
- **TG_USER_ID** - список ID пользователей Telegram, которым будут отправляться уведомления

### 3. Настройка торговли (`settings.py`)

#### Основные параметры торговли

```python
SPOT_TOKEN = "BTC"  # Токен для spot торговли (BTC, ETH и т.д.)
POSITION_SIZE_PERCENT = 15  # Размер позиции в % от баланса USDC
STEP = 1000  # Шаг сетки (TP) в долларах
MAX_GRID_ORDERS = 90  # Максимальное количество ордеров в сетке
AGGR = 0.5  # Коэффициент агрессивности пирамидинга (0.1 - 1.0)
```

- **SPOT_TOKEN** - токен для торговли (по умолчанию BTC)
- **POSITION_SIZE_PERCENT** - процент от баланса USDC для каждого ордера
- **STEP** - шаг в долларах между уровнями TP ордеров
- **MAX_GRID_ORDERS** - максимальное количество ордеров в сетке (защита от перегрузки)
- **AGGR** - коэффициент агрессивности (чем выше, тем чаще срабатывает пирамидинг)

#### Настройка потоков

```python
THREADS = 0  # Количество одновременных потоков (0 = автоопределение)
```

При `THREADS = 0` бот автоматически определит количество потоков на основе количества аккаунтов.

## 🎯 Алгоритм торговли

Бот использует стратегию с автоматическим усреднением и пирамидингом. Основной цикл работы:

### Основной цикл (каждые 10 секунд)

1. **Пауза 10 секунд** - дает время ордерам появиться в API биржи
2. **Получение данных** - параллельно загружаются:
   - Текущая цена токена
   - Активные ордера
   - TP ордера
   - Балансы кошелька

### Модуль SET_TP (Выставление TP ордеров)

**Цель:** Автоматически выставлять TP ордера для всех новых покупок.

**Алгоритм:**
1. Получает историю последних 5 сделок
2. Фильтрует покупки (BUY), которых нет в базе данных
3. Для каждой новой покупки:
   - Рассчитывает цену TP: `TP_price = buy_price + STEP`
   - Проверяет баланс токена
   - Создает лимитный ордер на продажу (SELL)
   - Добавляет паузу 1 секунда между ордерами
   - Сохраняет timestamp в БД для предотвращения повторной обработки
4. После обработки всех покупок прерывает основную итерацию для начала нового цикла с паузой

### Модуль проверки исполнения TP

**Цель:** Отслеживать исполнение TP ордеров и рассчитывать прибыль.

**Алгоритм:**
1. Сравнивает текущие TP ордера с предыдущим состоянием
2. Если TP ордер исчез из списка активных:
   - Находит связанную покупку по размеру и времени
   - Рассчитывает прибыль с учетом комиссий
   - Записывает статистику в Excel
   - Отправляет уведомление в Telegram
   - Обновляет балансы

### Модуль усреднения (Averaging)

**Цель:** Покупать токены при падении цены для усреднения позиции.

**Условие срабатывания:**
```
current_price < min_TP_price - STEP * 2
```

**Алгоритм:**
1. Проверяет наличие активных лимитных ордеров на покупку
2. Если лимитных ордеров нет:
   - Рассчитывает целевую цену: `target_price = min_TP_price - STEP * 2`
   - Если TP ордеров нет: `target_price = current_price - STEP`
   - Проверяет достаточность баланса USDC
   - Проверяет минимальный размер ордера
   - Создает лимитный ордер на покупку (BUY LIMIT)
   - После исполнения автоматически создается TP ордер (через модуль SET_TP)

### Модуль пирамидинга (Pyramiding)

**Цель:** Покупать дополнительные токены при росте цены для увеличения прибыли.

**Условие срабатывания:**
```
current_price > max_TP_price - STEP * AGGR
```

**Алгоритм:**
1. Проверяет наличие активных TP ордеров
2. Если есть TP ордера:
   - Рассчитывает уровень триггера: `trigger_level = max_TP_price - STEP * AGGR`
   - Если текущая цена выше триггера:
     - Проверяет достаточность баланса USDC
     - Создает маркет ордер на покупку (BUY MARKET)
     - После исполнения автоматически создается TP ордер (через модуль SET_TP)

### Пример работы алгоритма

**Сценарий 1: Первая покупка**
1. Нет TP ордеров → маркет покупка по текущей цене
2. Создается TP ордер на `current_price + STEP`

**Сценарий 2: Усреднение при падении**
1. Цена упала: `current_price = $90,000`, `min_TP = $95,000`, `STEP = $1,000`
2. Условие: `$90,000 < $95,000 - $1,000 * 2 = $93,000` ✅
3. Создается лимитный ордер на покупку по `$93,000`
4. После исполнения создается TP на `$94,000`

**Сценарий 3: Пирамидинг при росте**
1. Цена выросла: `current_price = $96,500`, `max_TP = $97,000`, `STEP = $1,000`, `AGGR = 0.5`
2. Условие: `$96,500 > $97,000 - $1,000 * 0.5 = $96,500` ✅
3. Создается маркет ордер на покупку
4. После исполнения создается TP на `$96,500 + $1,000 = $97,500`

## 🚀 Запуск

### Запуск бота

```bash
python main.py
```

### Выбор режима работы

После запуска появится меню с режимами:

1. **Averaging Market (0)** - Основной режим торговли с усреднением и пирамидингом
2. **Cancel Orders (4)** - Отмена всех активных ордеров
3. **Parse (5)** - Парсинг и диагностика аккаунта

### Работа с базой данных

Перед первым запуском режима торговли необходимо создать модули в базе данных:

1. Выберите режим создания модулей из базы данных
2. Бот автоматически создаст записи для всех кошельков из `wallets.txt`

## 📝 Дополнительная информация

### Параметры стратегии

- **STEP** - определяет расстояние между уровнями TP ордеров
- **POSITION_SIZE_PERCENT** - размер каждой позиции относительно баланса
- **AGGR** - агрессивность пирамидинга (чем выше, тем чаще покупки при росте)
- **MAX_GRID_ORDERS** - защита от создания слишком большого количества ордеров

### Ограничения

- Минимальный размер ордера определяется биржей (загружается автоматически)
- Комиссия биржи: ~0.0384% за сделку
- Задержка между итерациями: 10 секунд
- Пауза между созданием TP ордеров: 1 секунда

### Производительность

- Поддержка многопоточной работы (несколько аккаунтов одновременно)
- Параллельная загрузка данных для оптимизации
- Кэширование лимитов токенов
- Ограничение частоты логов для уменьшения спама

## 🤝 Поддержка

При возникновении проблем:

1. **Проверьте логи** на ошибки (`hyperliquid_bot.log`)
2. **Убедитесь в правильности настроек** в `settings.py` и `input_data/`
3. **Проверьте баланс** кошелька
4. **Убедитесь в доступности** Hyperliquid API и RPC провайдера
5. **Проверьте подключение к базе данных** (если используется)

### Частые проблемы

**Проблема:** "Insufficient USDC balance"
- **Решение:** Увеличьте баланс USDC или уменьшите `POSITION_SIZE_PERCENT`

**Проблема:** "Failed to create TP order"
- **Решение:** Проверьте баланс токена и минимальный размер ордера

**Проблема:** "Database connection error"
- **Решение:** Проверьте настройки БД в `settings.py` или отключите БД (она опциональна)
