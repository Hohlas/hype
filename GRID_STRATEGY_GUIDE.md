# Руководство по сеточной стратегии торговли

## Обзор изменений

Бот был успешно переведен на сеточную стратегию торговли согласно вашим требованиям.

## Основные изменения

### 1. Новые настройки в `settings.py`
- `STEP = 200` - основной параметр сеточной стратегии (шаг расстановки ордеров в долларах)
- `POSITION_SIZE_PERCENT = 10` - размер открываемой позиции в % от баланса
- `MAX_GRID_ORDERS = 50` - максимальное количество ордеров в сетке

### 2. Новый модуль `modules/grid_strategy.py`
Реализует полную логику сеточной стратегии:
- Открытие первой позиции (First Position)
- Усреднение при падении цены: `current_price < min_TP_price - STEP*2`
- Пирамидинг при росте цены: `current_price > max_TP_price - STEP/2`
- Автоматическое создание TP ордеров: `TP_price = entry_price + STEP`

### 3. Обновленные логи и уведомления
- **Открытие позиции**: `💸 [Тип операции] at $[цена] | [количество]'TOKEN' ($[сумма]) | Free=$[баланс], Trying=$[сумма] ([процент]%), Notional=$[номинал]`
- **Take Profit**: `✅ Take Profit +$[прибыль] | Eq=$[эквити]`
- **Telegram успешные TP**: `🎯 Take Profit +$[прибыль] | Eq=$[эквити]`
- **Критические ошибки**: `🚨 Hyperliquid Bot | [аккаунт] ❌ Ошибка: [тип ошибки] 📝 Описание: [описание ошибки]`

## Как использовать

1. **Режим 0** - теперь запускает сеточную стратегию (Grid Strategy)
2. **Режим 1** - старая стратегия усреднения (Averaging Market Legacy)

## Логика работы

1. **Первая позиция**: Если нет открытых позиций, открывается маркет ордер на покупку
2. **TP ордер**: Для каждой покупки сразу создается лимитный ордер на продажу по цене `entry_price + STEP`
3. **Усреднение**: При падении цены ниже `min_TP_price - STEP*2` открывается новая позиция
4. **Пирамидинг**: При росте цены выше `max_TP_price - STEP/2` открывается новая позиция
5. **Максимум ордеров**: Стратегия ограничена параметром `MAX_GRID_ORDERS`

## Настройка параметров

В файле `settings.py` можно изменить:
- `STEP` - шаг сетки (по умолчанию $200)
- `POSITION_SIZE_PERCENT` - размер позиции в % от баланса (по умолчанию 10%)
- `MAX_GRID_ORDERS` - максимальное количество ордеров (по умолчанию 50)

## Мониторинг

Все операции логируются в консоль и отправляются в Telegram согласно указанным форматам.
Критические ошибки отправляются в отдельный Telegram канал для мониторинга.
