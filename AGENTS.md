# Цель проекта
hype — бот для расстановки и контроля ордеров на https://app.hyperliquid.xyz.

# Качество решений
- Если входных данных недостаточно или они противоречивы — прямо укажи на это.
- Опирайся на проверяемые первоисточники — документы, содержащие информацию в исходном виде: официальная документация, стандарты и спецификации API. При использовании вторичных источников явно указывай их тип и происхождение.
- Подбирай решения прагматично, исходя из лучших практик. Отдавай приоритет обоснованности и точности решения, а не простоте реализации.
- При наличии альтернатив перечисли и аргументируй.
- Отдавай приоритет фактам и обоснованным выводам. Предположения, гипотезы и идеи помечай явно. Домыслы и спекуляции не приводи.

# Правила диалога
- Относись к моим идеям критически: не принимай их как истину без проверки — я могу быть некомпетентен.
- Возражай фактом, а не мнением. Ты не обязан соглашаться — обязан аргументировать.
- Задавай уточняющие вопросы, если запрос неоднозначен или требует дополнительного контекста.

# Правила ответов
- Отвечай простым русским языком.
- Объясняй через цель, причину и последствия.
- Избегай жаргона, англицизмов и узких терминов. Если термин необходим — объясни его при первом использовании.

# Обязательные правила
- Перед началом сессии прочитай `docs/project_description.md` (устройство и инварианты алгоритма) и `docs/CONTEXT_HANDOFF.md` (текущее живое состояние). Не обновляй их без команды, не дублируй информацию между ними.
- Для файлов более 60 Кб — только точечное чтение (Grep, Read с offset/limit), поиск через rg по ключевым словам.
- Зависимости — `requirements.txt`; виртуальное окружение — `./venv`.
- Тесты: `./venv/bin/python -m pytest tests/` — должны оставаться зелёными. Каталог `tests/` пока отсутствует: при добавлении тестов используй pytest.
- Для bugfix не делать рефакторинг «заодно».
- Секреты не коммитить, не печатать, не показывать: `input_data/*` (`wallets.txt`, `tg_bot_tokens.txt`), `databases/` (зашифрованная база), `settings.py`, ключи и логи.
- Для проверки синтаксиса/сборки: `./venv/bin/python -m compileall -q .`.

# Работа с рантаймом
- Прод живой: внешний планировщик (GitHub Actions / VPS cron) подхватывает `main` за минуты. Правки рантайма (`main.py`, `settings.py`, `modules/`) сразу влияют на боевое дежурство — после изменений обязательна проверка.
- В CI бот запускается неинтерактивно: режим передаётся переменной окружения (см. `docs/GithubActions.md`), а не меню `choose_mode()`.
- `git commit`, `git push` — только по явной просьбе пользователя.

# Структура проекта
```
.
├── main.py                     # Точка входа: логирование, режимы, запуск аккаунтов
├── settings.py                 # Запускаемая конфигурация (шаблон: settings.py.example)
├── requirements.txt            # Зависимости
├── README.md                   # Пользовательская документация
├── AGENTS.md                   # Инструкции для ИИ-агентов (этот файл)
├── modules/
│   ├── hyperliquid_browser.py       # HTTP-клиент Hyperliquid API (балансы, ордера, сделки)
│   ├── hyperliquid_client.py        # Оркестратор режимов для аккаунта (run_mode)
│   ├── delayed_orders_strategy.py   # Основная стратегия: сетка, тейки, учёт прибыли
│   ├── cancel_orders.py             # Отмена активных ордеров
│   ├── parse_mode.py                # Диагностика/парсинг данных аккаунта
│   ├── database.py                  # Хранилище модулей (JSON/шифр)
│   ├── wallet_loader.py             # Загрузка кошельков из input_data/wallets.txt
│   ├── tg_tokens_loader.py          # Загрузка Telegram-токенов
│   ├── retry.py                     # Повторы и типы ошибок
│   └── utils/                       # Утилиты, Telegram-отчёты, меню режимов, задержки
├── input_data/                 # Секреты (*.txt не коммитить; шаблоны *.txt.example в git)
├── databases/                  # Зашифрованное состояние (не коммитить)
└── docs/
    ├── project_description.md  # Устройство и инварианты алгоритма
    ├── spec.md                 # Спецификация
    ├── audit.md                # Аудит
    └── GithubActions.md        # Боевое дежурство через GitHub Actions
```
