# Алгоритм бота: спот-сетка с отложенными ордерами

> Фактическое поведение кода на `main` (`modules/delayed_orders_strategy.py`, `modules/hyperliquid_client.py`, `settings.py`). Параметры ниже — значения `main`: `SPOT_TOKEN=BTC`, `POSITION_SIZE_PERCENT=5`, `STEP=200`, `AGGR=0.5`.

## 1. Общий контур

Бесконечный цикл с паузой 10 сек (`:898-904`). Каждая итерация: цена, открытые ордера, TP-ордера, балансы (`:909-919`). Открытые ордера делятся на три группы: `buy_limit_orders` (лимитные BUY), `sell_orders` / TP (лимитные SELL), из SELL вычисляются `min_TP` / `max_TP` (`:1497-1502`). В каждый момент времени стратегия держит **не более одного активного BuyLimit снизу** (`:1650-1653`).

Размер каждого входа: `POSITION_SIZE_PERCENT` от **доступного** USDC, но не меньше биржевых минимумов (`hyperliquid_client.py:30-66`). По мере траты USDC следующие входы уменьшаются.

## 2. Три ветки входов

1. **First Position** — если TP-ордеров нет вообще (`min_TP == max_TP == 0`): маркет-BUY на `usdc_amount` по текущей цене (`:1549-1640`).
2. **Усреднение (вниз)** — лимитный BUY по цене `min_TP − STEP×2` (`:1642-1645`). Ставится только если нет активного BuyLimit (`:1653`); висит до исполнения. Устаревший лимит (цена ниже `min_TP − STEP×2.5`) отменяется (`:1780-1797`).
3. **Пирамидинг (вверх)** — маркет-BUY, если `current > max_TP − STEP×AGGR` (`:1799-1804`, `AGGR=0.5`). Срабатывает до обновления хая и сразу уводит `max_TP` выше.

## 3. Тейки и учёт прибыли

- Модуль **SET_TP** (`:991-1082`): каждую итерацию сверяет историю сделок с обработанными покупками; на каждую новую покупку ставит лимитный SELL целиком на `entry + STEP` (`:1060`).
- Исполнение TP детектируется исчезновением ордера из открытых + подтверждением в истории сделок (`find_matching_buy_trade`, `:113` — поиск покупки с тем же объёмом до времени выставления TP).
- Профит = выручка SELL минус затраты BUY по фактическим ценам и комиссиям из истории; fallback при ненайденной покупке — `STEP` минус 0.0144% на плечо (`:~1339-1351`). Операции пишутся в `hype_stat.xlsx` и Telegram.

## 4. Замечания к текущей логике

- `MAX_GRID_ORDERS=90` объявлен в `settings.py:9`, но в коде не используется — глубина сетки фактически ограничена только балансом USDC.
- Стоп-лоссов и отмены TP нет: убыточная позиция удерживается в споте неограниченно долго.
- Следствие для тренда: каждый вход продаётся целиком на `entry + STEP`, экспозиция в росте мала — сетка системно отстаёт от buy-and-hold (см. `docs/spec.md` §1).
