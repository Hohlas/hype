# Алгоритм бота: спот-сетка с отложенными ордерами

Параметры (имена — ключи `settings.py`):

- `SPOT_TOKEN` — торгуемый спот-актив (сейчас BTC).
- `STEP` — шаг сетки в долларах: расстояние усреднения и цель каждого тейка.
- `POSITION_SIZE_PERCENT` — размер одного входа в процентах от доступного USDC.
- `AGGR` — доля шага для входа вдогонку растущей цене (0.1–1.0).
- `BUYLIMIT_LEVEL_COOLDOWN_SEC` — пауза перед повторным входом на тот же уровень
  (константа, 600 с; в конфигурацию не вынесена).

## 1. Цикл

Итеративный цикл с паузой между итерациями. Каждая итерация получает: текущую
спот-цену, открытые ордера, балансы. Открытые ордера делятся на лимитные покупки
(BuyLimit, всегда не более одного активного) и лимитные продажи (тейки). По
висящим тейкам определяются `min_TP` (самая низкая цена продажи) и `max_TP`
(самая высокая).

Размер каждого входа — `POSITION_SIZE_PERCENT` от доступного USDC, но не ниже
биржевых минимумов. По мере траты USDC следующие входы уменьшаются; глубина
сетки ограничена только доступным USDC.

Дисциплина цикла — в `docs/GithubActions.md` (в дежурстве цикл ограничен вотчем;
в VPS-режиме бесконечный).

## 2. Три ветки входов

1. **Первый вход** — если висящих тейков нет вообще: покупка по рынку на размер
   входа по текущей цене. Повтор не допускается, пока для свежей покупки не
   подтверждён тейк (защита от дублей входов по одной цене).
2. **Усреднение вниз** — лимитный ордер на покупку по цене `min_TP − 2×STEP`.
   Ставится только при отсутствии активного BuyLimit и висит до исполнения.
   Устаревший ордер отменяется: если его цена оказалась ниже
   `min_TP − 2.5×STEP`, он снимается и выставляется заново по актуальной формуле.
3. **Вход вдогонку вверх** — покупка по рынку, если текущая цена выше
   `max_TP − AGGR×STEP`.

## 3. Правило повторного входа

Один исполненный вход — один тейк. Повторная покупка на том же ценовом уровне
запрещена, пока не подтверждено исполнение тейка предыдущего входа с этого
уровня. Нарушение запрета дополнительно сдерживается паузой
`BUYLIMIT_LEVEL_COOLDOWN_SEC` после исполнения тейка.

При старте бот находит покупки без тейков и ставит на них тейки; если для тейка
не хватает свободного остатка (меньше биржевого минимума), постановка
откладывается до появления баланса.

## 4. Тейки и учёт прибыли

На каждую новую покупку ставится лимитный ордер на продажу всего купленного
объёма по цене `вход + STEP`. Исполнение тейка подтверждается историей сделок.
Прибыль сделки = фактическая выручка продажи минус фактические затраты покупки
(цены и комиссии исполнения, при частичном исполнении — пропорционально проданной
доле). Если покупка в истории не найдена, прибыль оценивается как `STEP` минус
комиссии обеих сторон.

Каждая операция записывается в таблицу статистики (`hype_stat.csv`, стандартная
библиотека `csv`) и отправляется в Telegram.

## 5. Границы

Стоп-лоссов нет, тейки не отменяются и не двигаются: купленный актив удерживается
в споте неограниченно долго. В монотонном росте каждый вход продаётся целиком на
`вход + STEP`, поэтому позиция в тренде мала и сетка отстаёт от buy-and-hold.
