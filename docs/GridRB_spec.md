# GridRB — точная формализация

Соответствует коду: `research/backtest_lib.py`, класс `GridRB`.
Тестируемый набор параметров: **f₀=0.70, band=0.05, δ=0.5%, n=5, micro=on (lot 2% V, max 3)**.
Второй протестированный вариант: f₀=0.80, band=0.04, δ=0.4%, n=5.

---

## 1. Идея

GridRB — контроллер веса (ребалансер 70/30), «исполненный сеткой»: вместо рыночных
ребалансов при выходе веса BTC за полосу выставляются лестницы лимитных ордеров (maker),
а внутри полосы работает микро-сетка. Никаких индикаторов, трендовых фильтров, плеча,
шортов, стопов. Только спот, long-only. За всю жизнь стратегии ровно один маркет-ордер —
бутстрап на первом баре.

## 2. Исполнительная среда (без неё формализация неполна)

- Время дискретно: H1-бары i = 0, 1, 2, …; бар i → (o, h, l, c).
- Счёт: U — свободный USDC, B — количество BTC.
  V = U + B·c (капитал); w = B·c / V (вес BTC); пересчитываются на каждом close.
- Ордер: (уровень L, количество q, бар выставления p, тег).
- Лимитки (все — maker, комиссия 0.040%):
  - buy L активен с бара p+1; на баре i > p исполняется, если l ≤ L, по цене **min(o, L)**
    (гэп вниз — исполнение дешевле уровня);
  - sell S активен с бара p+1; на баре i > p исполняется, если h ≥ S, по цене **max(o, S)**
    (гэп вверх — исполнение дороже уровня);
  - внутри бара сначала исполняются все покупки, потом все продажи (худший порядок для лонга);
  - buy не исполняется, если q·px > U (остаётся висеть); sell исполняется на min(q, B);
    сделки и ордера с нотиналом < $10 (MIN_NOTIONAL) не исполняются.
- Маркет-ордер: исполнение по c с slip 0.020% и taker 0.070%.
- Резервы: free_usdc = U − Σ(нотинал висящих buy); reserved_sell = Σ(q висящих sell).
- Издержки: факт (maker 0.040% / taker 0.070% / slip 0.020%) и стресс ×2.

## 3. Параметры

| Символ | Значение | Смысл |
|---|---|---|
| f₀ | 0.70 | целевая доля BTC |
| band | 0.05 | полуширина полосы бездействия (±5 п.п.) |
| δ | 0.005 | шаг лестниц и микро-сетки (0.5% цены) |
| n | 5 | число уровней каждой лестницы |
| micro_lot | 0.02 | лот микро-сетки (2% от V) |
| micro_max | 3 | макс. одновременных микро-ордеров (обе ноги суммарно) |
| MIN_NOTIONAL | $10 | минимальный ордер |

Производные: зона продаж w⁺ = f₀+band = **0.75**; зона покупок w⁻ = f₀−band = **0.65**;
ширина микро-цикла 2δ = **1%**.

## 4. Внутреннее состояние

- first — флаг бутстрапа;
- trim_anchor, defc_anchor — close, от которого построена текущая лестница (∅ — нет лестницы);
- trim_ods, defc_ods — ссылки на висящие ордера лестниц.

Микро-сетка отдельного состояния не имеет (управляется тегами ордеров «micro»/«micro_take»).

## 5. Алгоритм (порядок внутри on_close: бутстрап → trim → defc → micro)

### 5.0 Бутстрап (бар 0)
`market_buy(f₀·V)` по close (taker+slip). Далее маркет-ордеров нет. После бутстрапа
w ≈ f₀ (+0.03 п.п. из-за комиссии) — внутри полосы.

### 5.1 Лестница продаж «trim» — зона w > 0.75

1. `q_tot = min( (w − f₀)·V/c , B − reserved_sell )` — весь избыток BTC над f₀
   (не над границей 0.75!), не больше свободного (нерезервированного) BTC.
2. Перестроить лестницу, если хотя бы один триггер:
   - **T1** — лестницы нет (trim_anchor = ∅);
   - **T2** — c > trim_anchor (close обновил максимум против якоря);
   - **T3** — лестница исчерпана (не осталось ни одного висящего trim-ордера).
   Перестроение: снять все trim-ордера; если q_tot·c < n·$10 → лестницы нет, якорь = ∅;
   иначе n sell-лимиток: **S_k = c·(1+k·δ), qty_k = q_tot/n, k = 1..n**; якорь = c.
3. Иначе (лестница стоит: c ≤ якоря и есть живые ордера): **уровни и якорь не менять**,
   пересчитать только объёмы: каждый живой уровень получает qty = q_tot/n
   (именно q_tot/n, а не q_tot/число живых).
4. Если w ≤ 0.75: снять все trim-ордера, якорь = ∅.

### 5.2 Лестница покупок «defc» — зона w < 0.65

1. `budget = min( (f₀ − w)·V , 0.999·U )` — объём докупки ровно до f₀
   (не до границы 0.65), не больше 99.9% баланса USDC.
2. Перестроить при тех же трёх триггерах (T1/T2/T3, якорь defc_anchor):
   снять все defc-ордера; если budget < n·$10 (=$50) → лестницы нет, якорь = ∅;
   иначе n buy-лимиток: **L_k = c·(1−k·δ), usd_k = budget/n, qty_k = usd_k/L_k, k = 1..n**;
   якорь = c.
3. Иначе: уровни и якорь не менять, пересчитать qty_k = (budget/n)/L_k.
4. Если w ≥ 0.65: снять все defc-ордера, якорь = ∅.

### 5.3 Микро-сетка — разрешена при w < 0.75

Не более одной новой заявки за бар:
1. n_micro = #(висящие buy «micro») + #(висящие sell «micro_take»).
2. Если n_micro < 3 и w < 0.75:
   `usd = min(0.02·V, free_usdc)`; если usd ≥ $10 — buy-лимит **L = c·(1−δ)**, qty = usd/L.

### 5.4 Реакция на исполнения (on_fill)

- Исполнен buy «micro» по цене px, объёмом q → немедленно выставить
  sell-лимит **px·(1+δ), qty = q** («micro_take», активен со следующего бара).
- Исполнения defc/trim — без реакций (у лестничных покупок нет своих тейков).

## 6. Точная семантика ключевых правил

**6.1 Храповик лестниц.** Обе лестницы перестраиваются только от последнего close и только
в трёх случаях: нет лестницы / close выше якоря / лестница исчерпана. При снижении цены
уровни замораживаются (объёмы обновляются, уровни нет) — цена «падает» в лестницу покупок
и наполняет её каскадом; после исчерпания (T3) лестница пере-armируется уже от новой,
более низкой цены. Продажи — зеркально: при росте выше якоря лестница подскакивает вверх
(T2), при исчерпании пере-armируется от новой цены. Итог: уровни покупок никогда не
двигаются вниз вслед за рынком, уровни продаж — никогда не остаются далеко внизу при росте.

**6.2 Выход только весовой.** У покупок defc нет индивидуальных тейк-профитов. Вся докупленная
часть продаётся только через trim-лестницу при w > 0.75; суммарный объём trim = избыток над
f₀. Если весь trim исполнится, вес вернётся точно к f₀ = 0.70.

**6.3 Микро-цикл.** Вход на c·(1−δ), тейк на fill·(1+δ) от фактической цены входа.
Валовая прибыль цикла +2δ = +1.00%; нетто ≈ **+0.92%** (две maker-комиссии по 0.04%).
Гэп вниз только улучшает вход (fill = min(o,L)); тейк всегда +δ к фактической себестоимости.

**6.4 Микро-сетка катится за ценой.** Каждый бар — максимум один новый micro-buy на 0.5%
ниже последнего close. Ордера «micro»/«micro_take» никогда не снимаются и не переставляются.
Одновременно ≤ 3 микро-ордера (обе ноги). В зоне w ≥ 0.75 новые micro-buy запрещены,
но уже висящие micro_take продолжают работать.

**6.5 Субординация кэша.** micro берёт деньги только из free_usdc (за вычетом резерва defc).
budget defc ≤ 0.999·U. Особенность реализации: при перестроении defc не вычитает висящие
micro-заявки из лимита, поэтому суммарная подписка может превысить U максимум на
3·0.02·V ≈ 6% V — движок это гасит: ордер, на который не хватило кэша в момент касания,
не исполняется и остаётся висеть; приоритет кэша — порядок выставления.

**6.6 Асимметрия объёмов.** defc делит бюджет поровну в USD → нижние уровни покупают больше
BTC (усреднение с усилением). trim делит поровну в BTC.

**6.7 Режимы по весу:**

| Зона | trim | defc | micro-buy | micro-take |
|---|---|---|---|---|
| w > 0.75 | да | нет | нет | работают |
| 0.65 ≤ w ≤ 0.75 | нет | нет | да | работают |
| w < 0.65 | нет | да | да (из free_usdc) | работают |

**6.8 Инварианты.** Σ(нотинал висящих buy) ≤ 0.999·U + 6%·V (см. 6.5); Σ(q висящих sell) ≤ B;
все ордера maker, кроме одного бутстрапа; продажи только из имеющегося B (no shorts).

## 7. Псевдокод (1-в-1 с кодом)

```
on_fill(ev):
    if ev = buy(tag="micro") исполнен по px, объёмом q:
        place_sell_limit(px*(1+δ), q, tag="micro_take", active_from=i+1)

on_close(i, c):
    if first: market_buy(f0*V); first=False          # единственный маркет за жизнь
    V = U + B*c;  w = B*c/V

    # ---- TRIM (продажи избытка) ----
    alive = any(trim_ods resting)
    if w > f0+band:
        q_tot = min((w-f0)*V/c, B - reserved_sell)
        if trim_anchor is None or c > trim_anchor or not alive:      # T1|T2|T3
            cancel_all(trim_ods); trim_ods=[]
            if q_tot*c >= n*MIN_NOTIONAL:
                for k in 1..n: place_sell(c*(1+k*δ), qty=q_tot/n, tag="trim")
                trim_anchor = c
            else: trim_anchor = None
        else:
            for od in trim_ods: od.qty = q_tot/n     # уровни не трогаем
    else:
        cancel_all(trim_ods); trim_ods=[]; trim_anchor=None

    # ---- DEFC (докупка к цели) ----
    alive = any(defc_ods resting)
    if w < f0-band:
        budget = min((f0-w)*V, 0.999*U)
        if defc_anchor is None or c > defc_anchor or not alive:      # T1|T2|T3
            cancel_all(defc_ods); defc_ods=[]
            if budget >= n*MIN_NOTIONAL:
                for k in 1..n: place_buy(c*(1-k*δ), usd=budget/n, tag="defc")
                defc_anchor = c
            else: defc_anchor = None
        else:
            for od in defc_ods: od.qty = (budget/n)/od.price         # уровни не трогаем
    else:
        cancel_all(defc_ods); defc_ods=[]; defc_anchor=None

    # ---- MICRO ----
    n_micro = count(resting buys "micro") + count(resting sells "micro_take")
    if n_micro < 3 and w < f0+band:
        usd = min(0.02*V, free_usdc)
        if usd >= MIN_NOTIONAL: place_buy(c*(1-δ), usd=usd, tag="micro")
```

## 8. Чего в GridRB НЕТ (отличия от соседей)

- нет «вдогонки» маркетом при росте (как ClassicGrid);
- нет тейков «вход+STEP» (как ClassicGrid) — выход только весовой;
- нет привязки к ATH вообще (UserIdea, TrendGrid): якорь лестниц — последний close,
  а не исторический максимум;
- нет трендового фильтра и переключения режимов (TwoModes, TrendGrid);
- нет индикаторов: входные переменные — только w, c и собственные ордера.
