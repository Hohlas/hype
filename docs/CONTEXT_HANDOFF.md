# Живое состояние проекта (передача контекста)

Обновлено: 2026-10-14. Это текущее рабочее состояние, не устройство алгоритма
(оно в `docs/project_description.md`) и не архитектура дежурства (она в
`docs/GithubActions.md`). Не дублировать сюда эти два документа.

## Что сделано в этой сессии

Торговая сшивка дежурства (лестница §10 `GithubActions.md`, ступень 3), но
**выключенная**: прод по-прежнему только разбор.

- `settings.py` (+ `settings.py.example`) — переключатель `DUTY_MODE = "parse"`.
  Значения: `"parse"` (только чтение) / `"averaging"` (реальные ордера).
  Смена режима = коммит в `main` (осознанное решение владельца, аудируемо).
- `modules/utils/modes.py` — `get_duty_mode()`: неизвестное/пустое значение
  **безопасно** откатывает в `parse` (ошибка конфига не включает торговлю).
- `modules/duty.py` — `run_trading_iteration` диспетчеризует: `parse` →
  `duty_parse`, `averaging` → `duty_trade`; закрытие торговых сессий на выходе
  вахты (`_close_trade_clients_best_effort`).
- `modules/duty_trade.py` (новый) — одна итерация §5 на кошелёк. Вызывает
  **боевую** стратегию в режиме одного прохода, а не её копию (см. ниже).
- `modules/delayed_orders_strategy.py` — у `trade_delayed_orders_strategy`
  добавлены `max_iterations` (0 = прежний бесконечный цикл VPS; 1 = один
  полный проход и возврат) и `poll_interval_override`. Поведение по умолчанию
  не изменено.
- `tests/test_duty_trade.py` (новый, 8 тестов) — гейт режима, диспетчер,
  дымовой один проход стратегии без ордеров.

**Ключевое решение:** не выносили тело цикла-монолита (~1250 строк, ~10
внешних `continue`) и не писали вторую реализацию — вместо этого стратегия
получила режим «ровно N проходов», и дежурство вызывает тот же боевой код. Это
исключает расхождение двух реализаций и не трогает VPS-путь.

## Боевое окружение

- **VPS нет.** Основной рантайм — дежурство в GitHub Actions.
- Репозиторий `Hohlas/hype` — **public**, не форк, дефолтная ветка `main`.
  Проверка: `gh repo view Hohlas/hype --json visibility,isFork,defaultBranchRef`.
- Ветка `state` — только `state.json`, `leader.json`, `work.json` (протокол
  §1.1); кода в ней нет.
- Секреты (Secrets): `WALLETS_DATA` (1 кошелёк), `DB_ENCRYPTION_PASSWORD`,
  `TG_BOT_TOKEN`, `PROFIT_BOT_TOKEN`, `TG_USER_ID`. Залиты
  `scripts/push_hype_secrets.sh`.
- Воркфлоу `Hyperliquid Bot Duty` — state **active**, крон `7,19,33,46,58` UTC.
- Зависимости/тесты: `./venv/bin/python -m pytest tests/` (сейчас **29
  зелёных**), сборка `./venv/bin/python -m compileall -q .`.

## Открытые вопросы / риски

- Публичные журналы/артефакты раскрывают адреса кошелька и signer-агента
  (`hyperliquid_browser.py:60-65`) и балансы. Ключи не печатаются. Владелец
  14.10 решил **пока не маскировать**.
- Рождения плановых запусков редки (§15.1) — не путать частоту тиков
  расписания (~5/час) с частотой фактических запусков (часы).
- `parse_mode` шумит ошибками по USDC/USDT (нет цен для тикеров) — существующее
  поведение, к дежурству не относится.
- Сеть до `api.github.com` из рабочего окружения периодически рвётся — мешает
  только `gh`, на код и раннеры не влияет.
